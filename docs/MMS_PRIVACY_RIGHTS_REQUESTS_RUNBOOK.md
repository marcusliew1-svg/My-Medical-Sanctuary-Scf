# MMS Privacy Rights Requests & Human Review Runbook

**Document ID:** MMS-PRV-RUN-PRR-001  
**Status:** WORKING DRAFT

## Scope

This runbook governs intake, identity verification, jurisdiction/applicability assessment, action evidence, response evidence and closure for privacy-related requests.

T6.40 does not claim that every request category is a legally available right in every jurisdiction. It does not verify the MMS controller identity, appoint a privacy officer, enable Production self-service or automate deletion.

## Request categories

The governance register can classify requests as:
- access;
- correction;
- deletion/erasure;
- withdrawal;
- objection;
- restriction;
- portability;
- complaint;
- other.

These are workflow categories only. Whether a particular right applies, and its timing/limitations, requires jurisdiction-specific assessment.

## Identity verification

Substantive disclosure or action must not occur until identity is verified using an approved process.

The governance register stores an internal/pseudonymous subject reference rather than unnecessary identity documents or raw personal details.

## Jurisdiction and applicability

Before fulfilment or denial, the accountable reviewer should record a jurisdiction/applicability assessment reference.

No statutory response period is invented by T6.40.

## Deletion and erasure

Deletion/erasure cannot be treated as automatically available or absolute.

Before a deletion/erasure request can be marked fulfilled:
- legal-hold state must be confirmed CLEAR;
- retention assessment must be documented;
- other preservation obligations must be considered.

This preserves T6.25 legal-hold and retention controls.

## Immutable action history

Material actions such as correction, export preparation, deletion/anonymisation, restriction, withdrawal recording, response, or denial require evidence and are written to the immutable action register.

If an action record is wrong, a correcting action is appended rather than rewriting history.

## Completion

A fulfilled, partially fulfilled or denied request requires:
- identity-verification evidence;
- jurisdiction/applicability assessment;
- decision evidence;
- response evidence;
- completion timestamp.

Denial requires an explicit reason.

## Production boundary

T6.40 does not create public forms, mailbox routing, automated identity verification, automated disclosure/export, automated deletion, or clinical-record modification.
